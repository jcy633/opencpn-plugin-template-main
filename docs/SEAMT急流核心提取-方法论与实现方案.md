## 0. 一句话

**SEAMT = 在冻结流速场里从入口断面撒一族流线，用形式积分量 T = ∫ds/|u| 全局评分，
T 最小的那条就是急流核心；顺带用 T 对出口纬度的曲线客观识别分叉。**
作为**独立于 Wang2026 的第二种主轴提取方法**落地，面向日本以南黑潮区。

### 0.1 实现原则（用户 2026-10-28 定，优先级高于一切细节）

> **SEAMT 天生抗涡**——它挑的是全局最小 T 的路径，绕涡的线 T 大自然被淘汰。
> **所以实现要忠于 Udalov 2026 原论文，只做必要的工程化改进。**
> 不要用别的论文的手段去"救"它。

**什么算"必要的工程化改进"**：

| 类别 | 例子 | 本方案中的体现 |
|---|---|---|
| (a) 论文没写、不写就没法实现 | 出口判据方向性、`fmod` 负数、RK4 冷启动 | §2.6、§2.2 |
| (b) 论文假定的数据条件与本插件不同 | 论文是 1/8° 固定、本插件任意 nc；论文是 AVISO L4、本插件是模式流场 | §2.4 CFL 推 Δt、§2.5-1 P₀ 平滑 |
| (c) 工程约束 | Win32 内存、渲染性能 | §2.9 释放、§6 |
| **不算** | **改变算法行为以"救"结果** | **平滑核心线、NaN 邻域搜索、强制推进、动态步长** |

### 0.2 适用域分工（两种方法不混用）

**两种方法各自论文规定的使用区域不同，是黑潮的不同河段，不是同一问题的两种解法。**

| | **Wang2026**（现有 `ncdf_kuroshio`） | **SEAMT**（本期） |

## 1. 方法本体（严格按 Udalov 2026）

### 1.1 问题形式化

给定有界域 Ω 内的二维水平速度场 **u**(x, y)（**当前时次** U/V，视为冻结场），
入口 Γ_in、出口 Γ_out。定义形式积分量

```
T = ∫ ds / |u|
```

**急流核心 = 所有成功流线中 T 最小者。** 变分意义与几何光学费马原理同构。

**重要澄清（写进 UI 文案）**：T 有时间量纲，但**不是质点的真实输运时间**。
本插件用逐小时数据，冻结假设在 T≈15–50 天量级上显然不成立——
**T 只能当"输运效率指数"用，不能当通过时间**。

### 1.2 四阶段算法（论文 Fig. 1）

| 阶段 | 操作 |
|---|---|
| **1. 初始条件集合** | 在 Γ_in 上取流速模最大点 P₀，布撒起点集合 {Pᵢ} |
| **2. 构造流线族** | 对每个 Pᵢ 数值积分 dr/dt = u(x,y)（冻结场） |
| **3. 筛选成功流线** | 取到达 Γ_out 的子集 G（G 为空 = "无贯通急流"，是物理诊断不是失败） |
| **4. 选最优流线** | G 中 T 最小者即瞬时核心 |

**关键点**：核心**不保证从 P₀ 出发**——"入口点本身也是优化变量"。这是与 KLSM 的本质区别。

## 2. 数值实现细则

### 2.1 坐标与度量

用经纬度自变量、球面度量进右端项：

```
dλ/dt = (180/π) · u / (R·1000 · cos φ)     [deg/s]
dφ/dt = (180/π) · v / (R·1000)             [deg/s]
```

`R = 6371.0`（与 `ncdf_kuroshio.cpp` 的 `kREarth` 一致），u、v 单位 m/s。
研究域 25–41°N，`cos φ` 远离 0。每步重算 `cos φ`，无累积误差。

### 2.2 积分格式：RK4，固定时间步

```
k1 = F(r_n)
k2 = F(r_n + 0.5·Δt·k1)
k3 = F(r_n + 0.5·Δt·k2)
k4 = F(r_n + Δt·k3)
r_{n+1} = r_n + (Δt/6)·(k1 + 2·k2 + 2·k3 + k4)
```

`F` = §2.1 右端项，速度用**双线性插值**（论文规定；不换渲染管线的 B 样条——
B 样条近岸会过冲，CLAUDE.md 已记录）。

> **必须是固定时间步，不是固定空间步。** 现有 `integrateOneWay` 是"一步一个网格距"，
> 那样 `T = ∫ds/|u|` 的语义不成立。慢的地方必须步子小、步数多、T 自然大——
> **这正是方法的物理所在**，搞错就退化成另一个算法。

#### 2.2.1 为什么不做动态步长（决策记录）

Wan2026 §3.1.2.3 有动态步子：最近 3 个流向角最大角差 <30° 且 |u|>0.2 m/s → 步长 ×1.5；
不稳定 → ×0.8；其他 → base。**评估后决定不采用**，理由：

1. **性能不需要。** 全部 141 条流线固定步长只花 ~35 ms（§3.1）。
   动态步长的主要收益是效率，这里不成立。
2. **对 min-selection 方法有害。** SEAMT 是在 141 条之间**比大小**。
   动态步长让不同流线走不同步长序列 → **离散误差不同构** → 排序可能因误差而非物理翻转。
   固定步长下 141 条用同一套离散格式，误差可比，min-T 的结论才可信。
3. **判据本质是抗涡手段。** Wan2026 需要在涡里"活下来"所以要放慢；
   SEAMT **不需要在局部活下来**——它需要把绕涡路径**准确表示出来**，好让它的 T 正确地大。
   而 §0.1 已定：不用别的论文的手段去救 SEAMT。
4. **论文已验证步长不变性。** Δt = 0.03 d 与 0.05 d（CFL 0.46 → 0.76）核心位置无显著变化。
   Udalov 明确说"当 Δt 足够小时，该估计对步长的选取具有不变性"。
5. **忠实性。** §0.1 原则：忠于原文。动态步长是**改变算法行为**，不属于 (a)(b)(c) 三类必要改进。

**但保留它带来的两个产物**（它们是校验，不是算法改动）：

- **步长收敛检验**（§8.1-3）：`Δt → Δt/2` 重算，核心线移动 < 1 网格距。这是真正的安全网。
- **RK4 vs RK2 一致性检验**（§8.1-4）：见下。

#### 2.2.2 为什么 SEAMT 用 RK4、Wang2026 保持 RK2

| | **SEAMT** | **Wang2026（现有实现）** |
|---|---|---|
| 论文/官方 | Udalov 明确 **4th-order Runge-Kutta** | 官方 MATLAB 是 **RK2 中点法** |
| 流线的作用 | **就是输出**，min-T 直接在上面比 | 只是**骨架**，之后被 55 km 高斯平滑 + 垂断面最大流速校正覆盖 |
| 精度要求 | 高：141 条比大小，相位误差会翻转排序 | 低：轴位置由校正步决定，不是由流线决定 |
| 每步采样 | 4 次 | 2 次 |
| 总耗时 | ~35 ms | — |
| **结论** | **RK4** | **保持 RK2** |

**SEAMT 必须 RK4 的核心理由**：它是 min-selection。RK4 局部误差 O(Δt⁵)、全局 O(Δt⁴)；
RK2 是 O(Δt³)/O(Δt²)。在 ~750 步的路径上，RK2 的累积相位误差可能与**近简并候选之间的 T 差**
同量级，从而让赢家由误差决定而非物理。而 RK4 的代价是 35 ms vs 18 ms——**完全没有成本理由用 RK2**。

**Wang2026 不要改 RK4**：它的流线精度在下游被完全丢弃（平滑 + 校正），
换 RK4 只让采样翻倍、对轴位置零收益，还会偏离官方 MATLAB 的对照基准。

> 诚实的保留意见：双线性插值只有 C⁰（跨格线导数跳变），RK4 的形式阶数不会完全兑现。
> 但论文的论证是"急流尺度（几百 km）≫ 格距（~14 km），插值误差可忽略"，
> 且海洋粒子追踪的通行做法（TRACMASS、Ariane）正是 **RK4 + 双线性**。
> 实测由 §8.1-4 的 RK2/RK4 对照检验把关。

### 2.3 T 的计算

论文：`T = Δt × N`（N = 到达出口的步数）。固定步长下与 `∫ds/|u|` 严格等价
（沿流线 `ds = |u|dt`，故 `∫ds/|u| = ∫dt = N·Δt`）。

- **主判据**：`T_days = N × dtDays`
- **自检量**：`T_hav = Σ Δs_n / |u_n|`，Δs_n 用 haversine（相邻点距离），|u_n| 取该步起点速度模。
  相对差应 < 1%，超出记 `[seamt] WARN` 并在读数标出。

### 2.4 Δt 的选取（按 CFL 推，不硬编码）

Udalov 的 0.03 天是**按 CFL ≈ 0.46 从 1/8° 格距推出来的**，不是随手定的常数。
本插件接受任意 nc 文件、格距不定，所以**照搬它的推导过程**比照搬它的数字更忠实：

```
Δt = CFL_target · Δx_min / u_max_est        CFL_target = 0.5
```

- `Δx_min` = min(纬向格距, 经向格距) 换算成米（经向按研究域平均纬度折算）
- `u_max_est` = 研究域内 |u| 的 **99.5 分位**（避免单点异常压小步长）
- 钳制到 `[0.01, 0.05]` 天

| 数据分辨率 | Δx（30°N） | u_max 2 m/s 时的 Δt | 落点 |
|---|---|---|---|
| 1/36° | 2.7 km | 0.0094 d | 触底 → 0.01 d |
| **1/12°** | **8.0 km** | **0.028 d** | ✔ ≈ 论文 0.03 d |
| **1/8°** | **11.4 km** | **0.040 d** | ✔ 论文用的就是这档 |
| 1/4° | 22.8 km | 0.080 d | 封顶 → 0.05 d |

钳制上限 0.05 d 有依据：论文验证过 Δt = 0.05 d（CFL ≈ 0.76）结果无显著变化。
UI 上 `Δt [auto]天`，可手动填 0.03 强制复现论文。

**`N_max` 随 Δt 等比缩放**：`N_max = ceil(300.0 / dtDays)`，保持论文"形式积分量上限 300 天"
（10000 步 × 0.03 天）的语义不变。

**分辨率下限告警**：`Δx_min > 30 km`（≈1/3° 以上）分辨不出射流横结构，结果不可信——
日志 `[seamt] WARN` + 读数框提示，**但仍允许运行**。

### 2.5 种子集合（阶段 1）

| 项 | 论文值 | 本插件 |
|---|---|---|
| Γ_in | 130°E | 可配，默认 130°E |
| P₀ 搜索纬度带 | 28°–31°N | 可配，默认 28–31°N |
| P₀ 定义 | 带内 \|u\| 最大点 | **平滑剖面后取最大**（见下） |
| 集合规模 | 141 点（P₀ 南北各 70） | 可配，默认 141 |
| 半宽 | ±0.7° | 可配，默认 0.7° |

论文选参依据（可复现）：1993–2024 全期，130°E 处核心最大经向位移 ≤ 1.4°，故 ±0.7° 够；
201 点集合未产生更低 T 的新轨迹，证明 141 点已收敛。

**本插件的三处落地细节**：

1. **P₀ 检测要平滑**（类别 b 的必要改进）。模式流场噪声比 AVISO L4 大，
   `|u|` 剖面的单点最大可能跳到瞬变涡上；P₀ 偏 2°，整个 ±0.7° 集合就错过核心。
   → 沿 Γ_in 的 `|u|` 剖面做 **3 点高斯平滑（σ ≈ 0.03°）**后再取最大。
   注意：这只影响**种子布撒中心**，不改变任何流线的积分与 T 比选，不违反 §0.1。
2. 起点严格落在 Γ_in 经线上（不是网格点），速度由双线性插值得到。
3. 起点落在陆地/无数据（`isSea` 为假）→ 该起点标记失败，不进 G。
   `nPts` 取奇数保证关于 P₀ 对称，步长 = `halfWidthDeg / ((nPts−1)/2)`。

### 2.6 积分终止条件（阶段 2）

| 原因 | 判据 | 进 G |
|---|---|---|
| `EXIT` | 本步**东向**跨越 Γ_out（λ 从 < λ_out 变为 ≥ λ_out 且 Δλ > 0） | **是** |
| `OUTDOMAIN` | 落出研究域矩形框 | 否 |
| `AGROUND` | `isSea` 为假（高分辨率掩膜判陆，或数据缺测） | 否 |
| `MAXSTEP` | 步数 > N_max | 否 |

**就这四个，与论文一致，不要再加。** 原本考虑过再加一个 `LOOP`（位置重复检测，
借自 Wan2026）来提前掐断绕涡打转的流线，**已否决**：Udalov 的停止条件里没有它，
而最坏情况（141 条全打满 N_max）也只有 ~450 ms，是按钮点击能接受的量级。
按 §0.1「不是必要的工程化改进就不做」，省掉一段 O(n²) 历史比对和一个可能误伤
大弯曲路径的阈值。

**四处必须指定的细节**（Udalov 未写，属类别 (a)）：

1. **出口只认东向跨越**。延伸体/再循环有西向流，不加方向判定，一条东去又西回的流线
   会被误判为"到达出口"。
2. **取第一次东向穿越**。流线可能多次进出 Γ_out（擦边、回摆），只认第一次；
   出口点用跨越那一步**线性内插**到 λ = λ_out 得 φ_out。
3. **RK4 中间采样点（k2/k3）落在无效处时**，退化为用端点速度的低阶步
   （现有 `integrateOneWay` 对中点落陆就是这么处理的）。这只降精度、不伪造流线。
   该步记 flag 供诊断。
4. **不设 \|u\| 下限终止**。慢的地方 T 大本来就是要区分的信号，加下限会改变可比性。

### 2.7 成功集合与最优线

```
G = { 流线 : 终止原因 == EXIT }
core = argmin_{γ ∈ G} T(γ)          // T = Δt × N
```

- G 为空 → `ok = false`。论文把这定义为"无贯通急流"的物理诊断，**但要正确使用这个语义**：
  Udalov 1993–2024 逐日跑了 32 年，**每一天都拿到非空 G**（原文："For each day of the
  considered period (1993–2024), a non-empty ensemble of streamlines reaching Γ_out
  was successfully obtained"）。所以在黑潮海域出现 G 为空，
  **几乎总是数据 / 研究域 / 参数的问题，不是"黑潮断了"**——报错文案要写明这点，
  并指向 probe 诊断日志，不要让用户当成物理结论。
- **必须报 \|G\|**。若 \|G\|/141 < 0.3，集合被陆地/缺测吃掉大半，min-T 代表性存疑，警告

### 2.8 子射流 / 分叉识别（T(φ_out) 极小）

把 G 按 `φ_out` 升序排成 `{ (φ_i, T_i) }`。**论文判据**：T 低于左右两个最近邻点即为局部极小。

**两个必加的工程过滤**（Udalov 自述判据过简、会检出假支流）：

1. **最小纬度间隔** `minSepDeg`（默认 0.05°）：间隔小于它只留 T 更低者
2. **最小显著度** `minProminence`（默认 0.5 天）：`min(T_left, T_right) − T_i < 门槛` 则丢弃

两者可关（设 0 退回论文原始判据），CSV 同时报**原始极小数 / 过滤后数目**。
论文四个典型日的极小间隔都在 0.15° 以上，默认 0.05° 不误伤。

## 3. 可行性论证

### 3.1 计算量（固定步长）

日本以南域核心线长 ~1,300 km，均速 ~1 m/s → T ≈ 15 天 → N ≈ 500 步（Δt = 0.028 d）。

| 项 | 量 |
|---|---|
| 流线数 | 141 |
| 典型步数 | 400–1,300 |
| RK4 每步速度采样 | 4 次双线性 |
| 典型总采样 | 141 × 750 × 4 ≈ **42 万次** |
| 单次 `sample()`（均匀网格 O(1) 定位） | ~80 ns |
| **典型耗时** | **~35 ms** |
| 最坏（大量绕涡线打满 N_max） | ~450 ms |
| `parallelFor` 按流线并行（4 线程） | **~10 ms** |
| 若改 RK2 | ~18 ms（省的不值当） |

比现有 Wang2026 提取更便宜。

> ⚠️ 并行遵守 CLAUDE.md：**只用 POD 自旋锁 / 局部 `std::thread`**，
> 严禁 `static std::mutex`（插件加载期会调 `ncdfLog`，非平凡 static 的线程安全初始化
> 未就绪 → 挂死）。`parallelFor` 已是合规实现，直接复用。

### 3.2 内存（Win32 2 GB 约束）

| 阶段 | 占用 |
|---|---|
| 积分中（最坏 141 × 10⁴ 点 × 2 double） | 22.6 MB |
| 典型 | 2.9 MB |
| 选出后（核心 + T 表） | < 100 KB |

**完全不构成压力**，无需分块/降采样。

### 3.3 数据前置检查（不通过就在读数框说明原因）

| 检查 | 不通过的后果 |
|---|---|
| `hasCurrent()` | 无流场可积分 |
| 研究域被数据覆盖 | 种子点取不到 |
| `Δx_min ≤ 30 km` | **警告但仍允许**（分辨率下限） |
| 研究域内有效格点占比 > 30% | 缺测过多，集合被吃光 |
| 有有效 `timeIndex` | 冻结场没定义 |
| 竖直层 | 固定 `depth_idx = 0`（表层），与现有 `readTimeStepData` 一致；论文本就二维 |

### 3.4 复用点（零耦合，但复用基础件）

| 现有 | 用途 |
|---|---|
| `ncdfDataMessage::ucurr/vcurr/latValues/lonValues` | 流场数据源，直接绑定不复制 |

**刻意不复用**：`integrateOneWay`（固定空间步长，语义冲突）、

|---|---|

## 8. 验证方案

**目标：证明输出确实是一条流线、且确实是最优的那条。**

> KLSM 对照与 SST 锋面验证均已取消（用户 10-28）。
> 下面各项判据各自对应方法的一个必要性质，任何一项不过都说明实现有 bug。

### 8.1 数值自检（实现完立刻做，全自动，进日志）

| # | 检验 | 判据 | 对应什么性质 |
|---|---|---|---|
| 1 | **切向一致性** | 核心线上每点 `atan2(v,u)` 与线切向的角差，**中位数 < 5°** | **输出确实是流线**。一旦对核心线做过平滑会立刻露馅。成本：一次遍历 |
| 2 | T 一致性 | `\|T_hav − N·Δt\| / (N·Δt) < 1%` | T 累加与度量正确 |
| 3 | **步长收敛** | `Δt → Δt/2` 重算，核心线横向距离中位数 **< 1 网格距** | 离散误差可控（论文的稳健性检验） |
| 4 | **RK2 vs RK4** | 用 RK2 复算，核心线横向距离中位数 < 1 网格距，且 **min-T 排序结论不变** | 量化 RK4 的必要性；若 RK2 已够用，说明 Δt 选得够小 |
| 5 | 集合收敛 | 141 → 201 点，min-T 不再下降 | 集合代表性（论文检验） |
| 6 | 度量对称 | 同路径正反算长度差 < 0.1% | haversine 实现正确 |
| 7 | 集合健康 | \|G\|/141 > 0.5，否则警告 | 集合没被缺测吃光 |

**第 1 项是核心**。它不需要任何外部数据，就能证明"我们输出的是一条流线"——
而"是一条流线"正是 SEAMT 区别于一切断面追踪法的本质特征。

> **为什么没有"与 Wang2026 交叉验证"**：两法适用域不重叠（§0.2），
> Wang2026 在 115–132°E 上游、SEAMT 在 130°E 以东的下游，**没有共同的轴可以对照**。
> 硬凑出来的"对比"只会误导。跨域比较留作后续独立课题。
> 共用 `ncdf_uvfield.h` 已经把"取速度"这个变量控制住了，将来真要比较时差异才归因于算法。

### 8.2 抗涡检验（对应方法的核心卖点）

在有明显脱落涡的日子看图：

- **判据**：核心线**不得绕任何涡心闭合/绕圈**。量化：核心线的累计绝对曲率
  （相邻段转角之和）应 < 某阈值（初值 360°，实测标定）；或核心线不自相交
- 这是 Udalov Fig 6b 的定性结论（KLSM 被涡捕获绕一圈、SEAMT 从涡南侧穿过），
  但**不依赖 KLSM 实现**——直接看 SEAMT 的输出有没有绕圈

### 8.3 物理合理性（人工看图）

- 核心线贴着流速模高值带走
- `T ≈ L / ū` 自洽
- 起点纬度 φ_in 可能 ≠ P₀ 纬度 —— 方法特性不是 bug（Udalov Fig 6 明确展示）

**测试数据**：`E:\nc1\海流2.nc`（CMEMS GLO12，1/12°，全球，4 个逐小时时次，表层，
`_FillValue = NaNf`，经度 −180..180）。分辨率、覆盖、层位都满足。
**只有 4 个时次** → 本插件做**单时次提取**，日尺度统计/趋势不在范围（CSV 导出可离线做）。

| `latDomMax`（日本以南） | 36.0 | **38.0** | 见 §12.3，**这是本轮最大的 bug** |
| `minProminence` | 0.5 d | **0.1 d** | 0.5 会把真正的分叉杀掉，见 §12.4 |
| `minSepDeg` | 0.05° | 0.05°（不变） | |
| `Δt` | CFL=0.5 自适应 | 不变 | 实测收敛良好，见 §12.5 |
| `LOOP` 终止判据 | 已否决 | 仍不做 | |

## 12.2 种子集合：141 太稀，改 281

**论文的 141 点（间距 0.01°）是为 AVISO（1/8°、平滑场）验证的。** 本插件 1/12° 模式数据上
`T(起始纬度)` **不平滑**——窄的最优带与分隔线交错：

| 间距 | npts | min-T | 是否含最优种子 31.0196 |
|---|---|---|---|
| 0.0100 | 141 | 11.682 | ✓ |
| 0.0070 | 201 | **33.394** | ✗（0.01/0.007 非整数） |
| 0.0050 | 281 | 11.467 | ✓ |
| 0.0033 | 421 | **11.304** | ✓ |
| 0.0025 | 561 | 11.386 | ✓ |

0.007° 那行是**唯一错过最优带**的间距，纯属巧合，却让 min-T 从 11.68 跳到 33.39。
取 **281 点**（间距 0.005°，是 141 的超集，min-T 只会更优），耗时约 2 倍（387 ms）。

> ⚠️ **教训：集合收敛检验必须用超集。** 我最初用 `nPts=201` 当"加密"来对照，
> 但 201 点的种子集**不是** 141 点的超集（间距不同），min-T 反而可能变大，检验完全失效。
> 正确做法是**间距减半**：`nPts' = 2·(nPts−1)+1`。这样 min-T 只降不升，比较才有意义。

## 12.3 ★ 研究域边界在剪流（本轮最重要的 bug）

**现象**：同一个问题在不同步长下给出**完全不同的答案**。

| Δt | CFL | min-T | 步长收敛自检 |
|---|---|---|---|
| 0.0296（自动） | 0.500 | **11.688** | 15.49 km ❌ |
| 0.0148 | 0.250 | **33.494** | 0.022 km |
| 0.0074 | 0.125 | **33.493** | 0.0015 km |
| 0.0037 | 0.063 | **33.493** | 0.0009 km |

**根因**：核心流线跑到 **(141.96°E, 35.999°N)**，离 Γ_out = 142°E 只差 0.04°，
却撞上了研究域北墙 `latDomMax = 36.0`。

- **粗步长**（末步 5 km）：一步跨过墙角落到 142°E 以东 → 判 **EXIT**（**侥幸对**）
- **细步长**（末步 0.6 km）：规矩撞北墙 → 判 **OUTDOMAIN**，绕行路径反而成了赢家

也就是说**粗步长那个"正确答案"是假的对**，靠步长跨过墙角蒙对的。
细步长下的 `T=33.49` 那条是 2104 km 的绕行路径（纬度来回跳 30.2↔33.8°N），不是黑潮。

**修法**：
1. `latDomMax` 放宽到 **38°N**（日本以南预设），给黑潮延伸体留余量
2. 新增 **`near_miss` 诊断**：出域但离 Γ_out 0.2° 以内的流线条数。**非 0 就说明边界在剪流**

修完后四个步长收敛到 **T = 11.684 ± 0.002**，`near_miss=0`。

> ⚠️ **教训：边界剪流的表象是"步长不收敛"。** 我一开始把它当成积分精度问题，
> 差点去调 CFL。真正该做的是**先看两条核心线的实际坐标**——粗的那条单调东北—正东
> 压在强流带上（是黑潮），细的那条 2104 km 来回绕（是被涡捕获的路径）。
> **几何比数字更早暴露真相。**

## 12.4 子射流显著度阈值 0.5 d 太严

281 点下 `T(φ_out)` 只有 16 点、2 个极小，非常平滑：

```
35.596, 33.82 ┐
35.599, 33.49 │  慢分支簇
35.601, 33.33 ← 局部极小（显著度 0.25）
35.603, 33.58 ┘
35.818, 11.47 ← 全局极小（显著度 0.21）★
36.013, 11.68
```

冠军 35.818°N（T=11.47）的右邻居 36.013°N（T=11.68）离它只有 **0.21 d**，
被 `minProminence = 0.5` 判为不显著 —— 而这两个正是**效率只差 1.8% 的两条分支**，
是应该报出来的分叉。降到 **0.1 d** 后 `subjets=2`。

同时要注意：**加密集合后噪声本来就低**（16 点只有 2 个极小），
论文担心的"噪声假支流"在稀疏集合下才严重。所以阈值应随集合密度调整。

## 12.5 步长收敛（修完 §12.3 后）

| Δt | min-T | 路径长 | `halfdt_dist` |
|---|---|---|---|
| 0.0296 | 11.6820 | 1230.65 km | 0.197 km |
| 0.0148 | 11.6839 | 1230.69 km | 0.025 km |
| 0.0074 | 11.6844 | 1230.71 km | 0.028 km |
| 0.0037 | 11.6838 | 1230.70 km | 0.005 km |

T 收敛到 **11.684 ± 0.002**（相对万分之二）。**CFL = 0.5 的自动步长是足够的**，
论文"Δt 足够小时对步长不变"的结论在此数据上成立——前提是研究域不剪流。

## 12.6 轴偏移问题的结论

设计稿里担心的"min-T 线偏离最大流速线"，实测：

| 集合 | 有符号偏移 | 绝对值 | 解读 |
|---|---|---|---|
| 141 点 | −6.70 km | 8.10 km | 恒偏一侧 |
| **281 点** | **−0.57 km** | **10.29 km** | **正负抵消，无系统性偏移** |

**281 点下有符号偏移 ≈ 0**，绝对值 10.3 km 是**双向的局部偏离**（弯道处），不是系统偏差。
之前的单侧偏移是稀疏集合挑到的那条路径的特性，不是方法本身的缺陷。

`core/max speed ratio ≈ 0.88` —— 核心线上的流速是断面最大流速的 88%。
这与论文一致（Fig 6a：SEAMT 比 KLSM 更平滑、路径更短、均速更低，二者本就不是同一条线）。

> ⚠️ **教训：判据要用对的量。** 我先后用"核心线自身曲率"和"速度脊曲率"去解释偏移，
> 都得不出相关性——因为**真正的原因是集合太稀**，跟曲率无关。
> 两轮错误归因后才靠加密集合看出真相。

# 14. 实测踩坑汇总（2026-10-29）

按"多久才意识到"排序，最贵的在前：

1. **研究域边界剪流**（§12.3）。表象是"步长不收敛、两个步长给出不同答案"。
   真正的诊断线索是**看两条核心线的实际坐标**，不是看数字。加 `near_miss` 计数后这类问题
   会自动暴露。
2. **收敛性检验要用超集**（§12.2）。拿"更密但不同格"的集合去对照，min-T 可能反而变大，
   检验完全无效。必须间距减半（`nPts' = 2·(nPts−1)+1`）。
3. **配对参数扫描不构成收敛检验**。我曾用 `halfwidth=0.2/0.4/0.7/1.2` 配 `npts=41/81/141/241`
   去扫，结论"6 倍宽度下核心不变 = 收敛"——但四组的**种子纬度完全相同**（间距都是 0.01°），
   必然不变。**扫描时要让自变量真的变**。
4. **错误归因两轮**：先用"核心线曲率"、再用"速度脊曲率"解释轴偏移，都无相关性。
   真因是集合太稀。**连续两次归因失败就该换角度，而不是继续加判据**（CLAUDE.md 已有此教训）。
5. **`MainDialog` 是点工具栏才构造的**。自动测试钩子挂在构造函数里完全不触发，
   必须挂在 `ncdf_pi::Init()`。
6. **提取路径不能碰颜色图状态**。`setData(dataChanged=true)` 会 `clearCoefficients()`
   删掉四层 GPU 纹理，而重建只在 `onTreeSelectionChanged` 的 Phase 2 做 ——
   颜色图会直接消失。而且 Phase 2 会 `swap` 释放 `myMessage.ucurr/vcurr`（数据活在
   float 网格里），`hasCurrent()` 恒为假，**所以这个分支每次点提取都会进**。
7. **单位坑**：`kMPerDegLat` 是**米**/度，用它算出的距离是米。我把它当公里报，
   导致"偏移 3004 km"这种不可能的数字，还让断面诊断只扫了 ±6.7 km 而非 ±60 km，
   得出"ratio=0.998、核心贴着轴"的错误结论。**涉及物理量的诊断要先核对量纲。**
8. **西里尔字母混进标识符**：`SeamтTrace`（т 是 U+0442）会编译失败。写完 grep 一遍
   非 ASCII 标识符。
9. **测试脚本要部署 DLL**。我写的手动扫描循环只写请求文件不部署，跑的是旧 DLL，
   参数改了没反应，白查两轮。

# 16. 入口断面被岛屿堵死 → 轴跑偏（2026-10-30）

## 16.1 现象

在 `E:\nc1\全3.nc`（GLORYS12 全球 1/12°，hourly mean）上跑 SEAMT，
轴在中段拐进慢水绕大圈，明显偏离红带（急流）。用户判断：
**"筛选流线时只筛选能完美从开始面到终止面的流线，急流核心的流线被打断了"** —— 正确。

## 16.2 机制（比"中途被打断"更靠前）

`traceOne` 的终止条件里，起点处取不到速度就直接丢弃：

```cpp
if (!rk4Advance(...)) { t.reason = SEAMT_AGROUND; break; }   // k1 取不到速度 → 起不了步
...
if (lon < lonOut && lon1 >= lonOut && lon1 > lon) { ... SEAMT_EXIT; return; }  // 唯一成功出口
if (!F.isSea(lon1, lat1)) { t.reason = SEAMT_AGROUND; break; }
```

而 **min-T 只在 `SEAMT_EXIT` 的流线里比**（`if (traces[i].reason == SEAMT_EXIT) G.push_back(i);`），
AGROUND / OUTDOMAIN 的完全不参与。

**T(φ) 实测剖面（Γ_in=131°E，2026-10-30）：**

```
30.250  EXIT     nSteps=3956   T=111.33    ← 南侧最后一个能走通的
30.25 ─── 30.75  ▒▒ 完全没有种子（0.5°≈55 km 空白）▒▒
30.752 ─ 30.910  AGROUND  nSteps=0  T=0    ← 74 条，连第一步都走不出去
30.912  EXIT     nSteps=3749   T=105.50    ← 恢复
30.997  EXIT     nSteps=3696   T=104.0295  ← ★ min-T，选中这条
31.060 ─ 31.082  AGROUND  nSteps=99..136   ← 又一段断
```

**Γ_in=131°E 上 30.25–30.91°N（约 73 km）无法起步**，而急流核心正从那里穿过。
min-T 只能在北侧 17 km 窄带里挑，选到 30.997°N —— 轴自然偏离核心。

根因是 **GLORYS 1/12° 分辨出岛屿，那些格点是 NaN**；
论文用的 AVISO 是平滑过的地转流场，断面全线有值。
（这与 §12 记的"数据源差异"是同一件事，但**不是流速大小差**，
而是 **NaN 分布差把入口断面堵死**。）

## 16.3 修法：把 Γ_in 调到岛屿少的经度（数据适配）

# 17. 踩坑汇总（2026-11-02 补）

> §14 是方法论层面的修订，这一节是**实现/数据层面**踩到的坑。
> 完整叙述见 `docs/交接文档-2026-11-02-SEAMT小岛干扰与分段拼接.md`。

## 17.1 小岛/缺测会把急流线打断，而被打断的完全不参与比较

**机制**：`traceOne` 里落点 `!F.isSea()` 或 `rk4Advance` 取不到速度就判 `AGROUND` 丢弃；
而 **min-T 只在 `SEAMT_EXIT` 的流线里比**（`if (reason == SEAMT_EXIT) G.push_back(i)`）。

**实测**（`全3.nc`，Γ_in=130）：`degraded=116`（RK4 中间点无效、退化为低阶步）、
`AGROUND=63`、种子 `noData=200` —— **三处都在被小岛打散**。

**修法**：小缺口桥接（`bridgeGap`）。沿积分方向外推、逐格找最近有效点，
超 `maxBridgeKm`（默认 25 km ≈ 3 格距）才判 AGROUND；大陆/大岛仍正常终止。
实测 `AGROUND 63 → 5`，成功流线 `133 → 189`。
`ncdf_flags.txt` 写 `seamtBridgeKm=N` 可调，0=关闭。

**为什么不是零填充**：MATLAB 的 `sub_u(isnan|mask<1)=0` 只是让场**连续**，
零速会让流线停住（Δt 固定、位移 0）最终撞 `nMax` 判 MAXSTEP。
**要的是「跨过去」，不是「填 0」。**

## 17.2 `findP0` 会被"模长最大但流向不对"的点带偏

**原判据**「下游分量最大」挡不住朝北的假峰值。改为**按模长降序取第一个大致东向的点**
（`u>0` 且 `|atan2(v,u)| ≤ 45°`）。

**实测**：130°E 上跳过 20 个偏北假峰值（含 36.958°N 那个 78.2° 的）；
135°E 上一步命中（33.04°N，角 −2.2°）。

**但判据救不了坏断面**：130°E 上跳过 20 个之后剩下的最佳仍是 30.17°N
（0.495 m/s，非黑潮核），因为断面本身就没了真核。**判据是必要条件，不是充分条件。**

## 17.3 种子带是 `P₀ ± halfWidthDeg`，不是 `latP0Min/latP0Max`

**`latP0Min/latP0Max` 只是 P₀ 的搜索范围**（在 Γ_in 哪一段找核），
**种子的实际跨度是 `P₀ ± halfWidthDeg`**（默认 ±0.70°，被陆地/缺测挡住时可扩到 ±3×halfWidth）。

**判据**：日志 `[seamt] P0 = ... ensemble N pts +-hw`；或 `lat_in` **正好等于 `P₀±halfWidth`**
（说明 min-T 选到了种子带边缘，真最小值在带外）。

**实测**（`全3.nc`，Γ_in=132）：`P0=27.92`、`lat_in=28.6164 = 27.9164+0.70` 精确吻合，
而真核在 32–33°N —— **够不着**。

**加宽 `halfWidthDeg` 无益**：`hw=3.00` 时 ubar 反而从 0.80 掉到 0.68
（把 P₀ 之外的慢流线纳了进来）。**问题在 P₀ 位置，不在跨度。**

## 17.4 Δt 走 CFL 自动在弱流场会失效

```cpp
dtDays = cflTarget * (dxMinKm*1000) / uMaxEst / 86400;   // 弱流 → dt 大
nMax   = ceil(300.0 / dtDays);
```
流速弱 → 每步位移小 → 走不到 Γ_out 就撞 `nMax`。

**实测**（`海流2.nc`）：`G=0/281`，`MAXSTEP=171`，流速探针显示全域只有 0.1–0.5 m/s。

**已改**：`dtDays` 默认固定 **0.03 天**（论文原始参数），`<=0` 才走 CFL 自动。
⚠️ **测试请求文件里写 `dt=0` 会强制走 CFL 自动**，别这么写。

## 17.5 出口判定原先只支持东向（隐藏缺陷）

```cpp
if (lon < lonOut && lon1 >= lonOut && lon1 > lon)   // 只认东向跨越
```
**西向段（反推）会被判成永远到不了出口。** 现按 `Γ_in → Γ_out` 方向判：
```cpp
const bool eastward = (lonOut > lonIn);
const bool crossed = eastward ? (lon < lonOut && lon1 >= lonOut && lon1 > lon)
                              : (lon > lonOut && lon1 <= lonOut && lon1 < lon);
```

## 17.6 分段拼接共用的是 P*，不是 P₀

**P₀ 是断面上"东向最强"的点，P* 是右段最终选中的那条流线的起点**，两者不等
（实测 135°E 上 `P0=33.0411`、`P*=33.2111`）。
两段要无缝对接，**公共点必须是 P\***。

用户设计：P* 自身能反推到 lonIn 就直接用；否则在 `P* ± halfWidth` 集合里找
能到达的最近点 P'，取 **`(P*+P')/2`** 作共有点。

## 17.7 反推段必须翻转流速方向

黑潮向东流，从 135 向西反推到 130 必须用 **(−u,−v)** 积分，否则根本走不到。
实现用 `dirSign = (lonOut > lonIn) ? 1.0 : -1.0` 乘在 `dtSec` 上。

**三个连带后果**：
1. **点序要反转**后再接右段
2. 反推段上**取流速/插值必须用真实的 (u,v)**，不能用积分时的 (−u,−v)
3. `tHav`（`Σ ds/|u|`）用模长，不受影响

## 17.8 选 Γ_in 不能只看"断面无缺口"

**必须同时看急流核落在断面的哪一纬度。** 132°E 断面最干净（28–33°N 有效点 101/101、
gap=0），但最大流速在 28°N（非黑潮核）→ ubar 0.37；
135/136°E 同样干净且核在 33°N → ubar 0.87~1.11，与论文 1.10 一致。

**验证方法**（5 个全球时次，见交接文档 §4）：量 `覆盖 / 最长缺口 / 断面最大|u|及其纬度 / 流向角`。
**流向角是最有效的判据** —— 130°E 是 55–71°、132°E 是 33–47°，都不是黑潮核。

## 17.9 GLORYS vs AVISO 的断面差异比流速差异更致命

| | AVISO（论文） | GLORYS 1/12° |
|---|---|---|
| 性质 | 卫星测高**地转流**，平滑 | **模式流场** |
| 130°E 断面 | 全线有值 | **32.5–33.5°N 是 NaN（岛屿）** |
| 贴岸核 | 清晰，1 m/s 量级 | **被吃掉** |

**同一条断面两套数据的"有效点数"可以差一倍**（131°E 的 28–33°N 带：GLORYS 52/101，
最长缺口 1.85°）。**换数据源先量断面有效点数，别直接套用旧参数。**

论文参数 + AVISO = **0.06% 复现**；论文参数 + GLORYS = **G=0/141 全灭**。
所以 `presetJapanSouth` / `presetPaperDomain` 是数据适配版，不能拿去复现论文。

## 18.2 缺陷 A：`lonDom` 把 Γ_in 当成了研究域的墙

`lonDomMin/Max` 原先直接取 `[min(lonIn,lonOut), max(lonIn,lonOut)]`，等于把 Γ_in / Γ_out
当成两堵墙。论文里 Γ_in 是研究域**内部**的一条切割断面：种子撒在断面上，流线起步时
带向西分量是正常的物理运动，不该被判"离开研究域"。

**实测（修复前）**：`全3.nc` Γ_in=130 时
```
OUTDOMAIN n=172  avgSteps=15  avgEnd=(130.000, 30.499)
```
**172/561 = 31% 的流线平均只走 15 步就"出域"，终点就压在 Γ_in 上**；而纬度域是
24–38°N（比轴线宽得多），两侧尺度完全不对称。

**修法**：`SeamtParams::lonPadDeg`（默认 1.5°），域 = `[min(lonIn,lonOut)−pad, max+pad]`；
`<=0` 退回旧行为便于回归。`estimateUMax` 仍按 `[lonIn,lonOut]` 统计（它只服务 CFL）。
**效果**：`OUTDOMAIN 172 → 0`，`G 380 → 452`。**但轴没变**（ū 0.367→0.371）——
它是个真缺陷，不是轴偏离的主因。

## 18.3 缺陷 B：`findP0` 挑到"最强的流"而不是"射流"

论文原文是 "the maximum velocity magnitude **of the jet flow**"。旧判据是
「按模长降序取第一个大致东向（`u>0` 且 `|atan2(v,u)|≤45°`）的点」——
2026-10-30 加的流向过滤确实挡掉了朝北的假峰值，但**挡不住"别的一支东向强流"**：

| Γ_in | 旧判据挑到 | 真正的黑潮核 | 后果 |
|---|---|---|---|
| 130 | 30.25°N（\|u\|=0.455） | **31.4°N**（\|u\|≈0.30，**更弱**） | 种子带只到 31.12°N，够不到 |
| 132 | 28.00°N（\|u\|=0.624） | **32°N** | 差 4 个纬度 |

**130°E 上黑潮比那支别的流更弱**，所以任何"按速度挑"的启发式都会挑错。

**修法：把"哪支是射流"交给算法自己的判据（min-T）。**
`findP0` 改为产出**候选列表**：`sm`（3 点高斯平滑模长）在 ±0.25° 窗口内的极大 +
下游分量 > 0 + 模长 ≥ 主候选的 0.15 倍，间距 < 0.5° 只留最强，最多 8 个。
每个候选各布一个 `P₀±halfWidth` 的集合，**并集**交给 min-T。
只有一个候选时完全退化成论文原算法。

**为什么用"窗口极大"而不是"三点局部极大 + 邻居相邻"**：贴岸急流常紧挨着缺测缺口
（130°E 上黑潮在 31.4°N，31.75°N 起就是 NaN），"邻居必须是相邻纬度"会把它当缺口假峰
滤掉 —— 2026-11-02 第一版就是这么漏掉黑潮的。**候选上限 4 也不够**：31.4°N 那支模长
只有 0.30，排在 37.17(0.77)/30.17(0.50)/29.08(0.38)/34.54(0.35) 之后第五位被截掉。

**效果**：

| Γ_in | 前 ū / lat_in | 后 ū / lat_in |
|---|---|---|
| 130 | 0.371 / 30.33 | **0.434 / 31.45** |
| 132 | 0.369 / 28.70 | **0.660 / 32.55** |
| 133 | 0.818 / 32.59 | 0.818 / 32.59（逐位不变）|
| 135 | 1.131 / 33.44 | 1.131 / 33.44（逐位不变）|

130°E 的 `lat_in=31.45` 与「分段拼接从 133°E 反推回 130°E」得到的 31.42°N 吻合 ——
**起点终于对了**。132°E 那 4 个纬度的错误直接消失。

## 18.4 证伪：近岸容错取样**不是**解药

假设：`UVField::sample()` 要求 2×2 四角全有效，每个岛屿周围被啃掉一圈有效海域，
岛链里被啃掉的正是黑潮的水道 → 急流被打散。为此加了 `sampleCoast`（四角里只要有一个
有效就取到值，权重按有效角归一化）+ `isSeaCoast`，SEAMT 侧按 `seamtCoastTolerant` 开关。

**A/B 实测（同数据同参数）**：

| Γ_in | 严格四角 ū / offset / ratio | 近岸容错 ū / offset / ratio |
|---|---|---|
| 130 | 0.371 / 35.0 km / 0.748 | 0.369 / 36.9 km / 0.717 |
| 131 | 0.438 / 26.4 km / 0.819 | 0.424 / 35.0 km / 0.570 |

`degraded`（1493→1）和 `AGROUND`（→0）确实没了，**但轴没变好、131°E 反而更差** ——
容错让流线能从"只有一个角是海"的格子里穿过 1–2 格的小岛抄近路。
**结论：四角规则啃掉近岸海域是真的，但急流跟丢另有原因。默认退回严格**，
方法留在 `UVField::sampleCoast`，`ncdf_flags.txt` 写 `seamtCoastTolerant=1` 可做对照。

**同理，`seamtBridgeKm=0`（关掉小缺口桥接）对照：ū 0.431 vs 0.434，轴完全一样。**
桥接也不是原因。

起点对了、前半段贴岸，**但 135°E 之后掉进急流南侧的再循环**。

**判定依据（三条独立证据都指向同一结论）**：

1. `Γ_in=130, Γ_out=135` 的 884 条成功流线，出口只落在 **32.2 / 32.4 / 36.4 / 36.6°N**

**⇒ 在 `全3.nc` 这个流场里，135°E/33.4°N 的黑潮流线不能一路反推回 130°E。**
自检也支持：`tangent=0.0014°`、`tHav=0.05%`、`halfdt=0.18 km`、`dense=0.23 km` 全绿 ——
不是积分精度问题，是流场本身在 131–133°E 一带（土噶喇—大隅—屋久岛链 + 南海侧弱流）
把急流的连通性切断了。这也和 §16 的观察一致：**黑潮在 130–132°E 只有 0.4–0.6 m/s、
弥散不成射流**，而 136°E 以东才是 1.4–1.7 m/s 的锐利急流。

**可用的绕法**（已实现，见 §3.3 分段拼接）：`splitlon=133` 时

# 19. `135→160` 轴偏离速度脊：根因是 153°E 的驻点（2026-11-02）

> 这是长期悬而未决的主问题：135→142 能识别出贴脊的路径，135→160 就偏得很远。

## 19.1 隔离实验：把 Γ_out 逐步东移

同数据（`全3.nc`）、同参数、Γ_in=135，只改 Γ_out：

| **152** | 18.71 d | 1930 km | 1.194 | **33.4313** | **13.0 / — km** | 555/1518 | 611 |

| **160** | 43.02 d | 3227 km | 0.868 | 33.2113 | **30.0 / 181 km** | 459/1518 | 707 |

**Γ_out 收在 152°E 之前，轴就贴脊（12–13 km，ratio 0.89）；越过 153°E 就崩。**
分界点正好落在 153.0°E —— 那里有一个驻点。

## 19.2 驻点：`(153.0°E, 36.3°N)`

**数据本身**（不是插值造的，36.3333/153.0000 就是原始格点）：

| 位置 | \|u\| | 流向 |
|---|---|---|
| 152.50°E, 36.25°N | **1.784** | 东 |
| 152.75°E, 36.25°N | 0.691 | 东 |
| **153.00°E, 36.25°N** | **0.050** | — |
| 153.00°E, 36.33°N | **0.018** | 西（−0.017, +0.005）|
| 153.25°E, 36.25°N | 0.162 | **西** |
| 153.00°E, 35.50°N | 1.568 | 东 |

**强东向射流在 153°E 就地终止，水体回流向西；真正的延续在南边 35.5°N 一带。**
36.3°N 那一支是条死路（涡的北缘）。

## 19.3 机制：急流流线被驻点吃掉

135→160 集合里种子的去向（`traces` 表）：

```
seed=33.4363  reason=3(MAXSTEP)  n=10000  T=300.15  end=(153.0078, 36.2996)
seed=33.4413  reason=3           n=10000  T=300.15  end=(153.0078, 36.2996)
… 33.2313 .. 33.7413 全部 MAXSTEP
成功的只有 33.1613 .. 33.2263 这一条 0.07° 宽的窄带
```

**`seed=33.4361` 正是 135→142 的最优种子** —— 它就是贴脊的黑潮流线，一路走到
153°E 然后死在驻点里。整条 33.23–33.74°N 的黑潮带都是同样下场。

于是 **min-T 只能在 33.16–33.23°N 那条窄带里挑**，而那条窄带在 139–142°E
是离脊的（所以轴在那里下凹到 31.9°N，速度脊在 34.0°N）。

**因果链**：
```
153°E 驻点 ── 吞掉 33.23–33.74°N 全部黑潮流线（含 135→142 的最优者）
          ── G 里只剩 33.16–33.23°N 的离脊流线
          ── min-T 选中它 ── 轴在 139–142°E 下凹（离脊 181 km）
```

**对照**：`T_core(135→160)=43.02 d`，而逐列速度脊折线 `T_ridge=48.16 d` ——
min-T 挑的那条确实更省，**不是 min-T 算错**，是贴脊那条根本进不了 G。

## 19.4 结论

**在 `全3.nc` 这个流场里，不存在"既贴速度脊、又能贯通到 160°E"的流线。**
贴脊那条（135°E/33.44）在 153°E 的驻点里终止；能通到 160°E 的只有南边那条离脊路线。
135→160 的轴是**唯一贯通路线**，它偏离速度脊是流场性质决定的，不是积分或选比的 bug。

自检也支持：`tangent=0.006°`、`tHav=0.01%`、`halfdt=0.04 km`、`dense=0.00 km` 全绿。

## 19.7 涡外缘绕行：把被涡吃掉的流线救回来（2026-11-02 已实现）

### 19.7.1 为什么"贴脊"和"绕涡"是两族

| | 139–142°E | 153°E | 种子（135°E） |
|---|---|---|---|
| family A（旧核心线） | 离脊 180 km ✗ | 绕涡 ✓ | 33.2113 |
| family B（135→142 核心） | **贴脊 13 km** ✓ | 被涡吸走 ✗ | **33.4313** |

两族在 135°E 上只隔 550 m（相邻两个种子），中间是分界线。**从 135°E 出发，没有一条同时具备两个属性**——除非把 family B 从涡里救出来。

### 19.7.2 三段拼接

```
段1  Γ_in ──→ 段1 截断点    正常 RK4，真流线
段2  截断点 ──→ 出口点       直线投射（T 按**等效步数 × Δt**，用户定）
段3  出口点 ──→ Γ_out        正常 RK4，真流线
```

- **涡心**：流线停滞时就地做 HEPTA 式雅可比分类
- **涡外缘**：Okubo-Weiss `W = S² − ω²` 确认是涡核（`W<0`）并给出涡核尺度；
  落点取「越过 W=0 之后 |u| 的径向极大」那一圈
- **多分支**：落点取环上速度最大的 4 个（流向朝 Γ_out），各积一条段3，**全部进 G**，
  由 min-T 分主次（呼应"鞍点分裂出多条通道"）
- 同一涡的段3 只算一次，被吸的流线共享

### 19.7.3 三次踩坑，都记下来

| 尝试 | 结果 | 原因 |
|---|---|---|
| 段2 沿 **W=0 等值线**绕弧 | T_arc **4.5 天**，必输 | W=0 是"涡核/外围"的动力学分界，穿过的正是涡内慢水（0.35 m/s） |
| 段2 沿**速度环**绕弧 | T_arc **5.7 天**，更差 | 环上只有西—西南侧是快水，其余 0.3–0.4 m/s |
| 段2 **径向直线** + 段1 截到 \|u\|≥0.3 | T=61.4，仍输 43.0 | **段1 截得不够早**，把涡里打转的 40 天算进了 T₁ |
| 段2 径向 + 段1 截到 **\|u\|≥1.0** | **T=35.5，胜出** ✅ | 段1 停在真正的射流上，T₁ 回到 18.7 天量级 |

## 19.8 涡绕行的五项优化（2026-11-05）

19.7 的实现留了 5 处启发式，都换成了「同一把尺子（min-T）」或客观判据：

| # | 原来 | 现在 |
|---|---|---|
| ① | 段2 写死「径向直线投射」（`seamtWrapArc` 手工开关）| **min-T 选路径**：「入口→沿速度环(min-T 弧)→出口」与「入口→出口直连」各积一次 T，取小的 |
| ② | 出口按 \|u\| 降序取前 4；入口钉死在"离捕获点最近" | **(入口, 出口) 组合按 T₂ 选优**，入口左右各试 `±entrySpan` 个环点；取前 `wrapBranches` 个**互不相同**的出口，各积一条段3，最后由 min-T 比 **T₁+T₂+T₃** |
| ③ | 段2 的 T 用**出口点的 \|u\| 代表整段** | `polylineTravelDays` **沿路径逐段取两端速度平均**积分 |
| ④ | 段1 截断只看 \|u\| 与离涡心距离 | 再加「**切向仍朝 Γ_out**」：`u·goutDir > 0`（刻意放宽到 90°，卡 45° 会把绕涡时正在转弯的候选全筛掉）|
| ⑤ | 无 | **强涡/弱涡分流**：`strength = 环上最大\|u\| / 射流速度`，低于 `wrapWeakFrac` 就不绕行 |

**「出口影响 T₃ 吗？」——影响，而且 T₃ 一直在参与比较。** `nt.T = T₁ + T₂ + T₃`，
`T₃ = wb.br.T`（出口点到 Γ_out 的续积分），G 的 min-T 比的就是这个总和。
原来的问题不在 T₃ 没算，而在**出口的预筛**只看 |u|、不看 T₂，「|u| 略小但段3 短得多」
的出口根本没被积分过。现在预筛按 T₂，段3 积完再由总 T 定胜负。

**射流速度必须取全域的。** 优化⑤ 第一版用「被捕获流线的局部最快」当射流速度，
结果 845 条流线在 (136.75,38.75) 的滞止区里爬、局部最快只有 0.3 m/s，
连 0.5 m/s 的弱涡都判成"比射流还强"。改成扫一遍全部流线取最大 |u|（=1.997 m/s）
后，5 个弱涡被正确跳过，只有 153°E 那个（环 1.775，strength 0.89）做绕行。

**段2 的 min-T 选路径，实测几乎总是直连胜出**（`seg2 path: arc=0 chord=71`）——
与 19.7 的结论一致（环上只有西侧是快水，绕整圈太慢）。保留 min-T 选择的价值在于
**不再是写死的**：遇到"速度环就是射流本身"的涡会自动改走弧。反例也见到了：
左段（130→133）的小涡上 `arc=1 chord=1`、`arc=1 chord=0`，弧确实赢过。

## 20.5 涡外边界的来源：论文没有，是自加的（2026-11-02 备查）

论文里与"涡"相关的只有两处，**都没有涡边界的算法**：

1. **§2.3 HEPTA**（Udalov & Uleysky 2026）只做**驻点的定位与分类**：
   > 基于网格单元内速度场的双线性（时间上为三线性）插值，以及**驻点附近运动方程雅可比矩阵的分析**。
   > 椭圆点对应涡旋结构的中心，双曲点对应鞍点，标志最大变形区。

   输出是驻点的**位置与类型**（图 2/3 的三角 / 叉号），不是边界。
   本插件的 `classifyCriticalPoint` 就是照这个做的。

2. **§2.1** 提到涡边界，但只是作为 SEAMT 的**思想来源**引用别人：
   > SEAMT 方法的思想渊源来自自动相干结构探测领域，其中**流线构造已成功用于定义涡旋边界**
   > （Sadarjoen and Post, 2000）。借鉴这一思想，我们重新框定任务……

   论文借的是"用流线构造相干结构"这个思路，转用来定义**急流核心**（min-T 流线），没做涡边界。

**⇒ 本插件的涡外边界是自加的工程化**，两步：

| 步骤 | 方法 | 来源 |
|---|---|---|
| 确认是涡 + 涡核尺度 | **Okubo-Weiss** `W = S² − ω²`，`W<0` = 涡度主导，`W=0` 半径 = rW | 涡检测领域标准判据（非论文）|
| 绕行用的外缘 | 越过 W=0 后，每个方位角上 **\|u\| 的径向极大**那一圈 | 自加（见 §19.7.3 的踩坑）|

论文里涡的**实际用法**是 §3.3「急流绕过涡核（核心环绕椭圆点 E1）」——那是**结果形态的描述**，不是边界定义。

## 20.8 分段拼接接缝：44.7 km 断点的根因与修法（2026-11-05）

### 20.8.1 「生硬」其实是断点，不是折角

改前量 `海流1.nc`（`splitLon=133`）的接缝：

```
299  132.98133  32.20871   seg  1.776 km   turn  0.58
300  133.00000  32.21115   seg  1.779 km   turn 77.20   <-- 左段到此
301  133.03389  32.61404   seg 44.661 km   turn 90.19   <-- 跳 44.7 km
302  133.06469  32.61209   seg  2.896 km   turn  0.15
```

全轴弦转角中位 0.71°、P99 7.46°，段长中位 2.34 km —— 接缝的 77°/90° 与 44.66 km
都是**离群点**。两段线根本没接上。

### 20.8.2 根因三条

1. **`latP0Forced = common` 只是「布种带的中心」，不是「从这一点出发」**。
   左段仍跑完整的 min-T 选优（nPts=281），于是"以 P\* 为起点反推"变成了
   "以 P\* 为**中心**再找一条更快的流"：左段起点落到 32.211°N，P\*=32.616°N。
2. **拼接无条件 `for (i = 2; ...)` 丢掉右段第 0 点（P\*）**。那只有在
   `left.core[0] == P\*` 时才是去重；现在不等，就等于丢掉了正确的一端。
3. **`(P\*+P')/2` 取中点的兜底**保证产生断点 —— 中点既不在左段上也不在右段上。

**更深一层**：拼出来的是**两条不同流线的硬接**，违反「核心必须是一条流线」。
而 `seamtTangentCheck` 报的是**中位数**，一个 90° 的坏点被 587 个好点稀释成
0.0138° —— 自检的盲区，所以一直没露馅。

### 20.8.3 修法（2026-11-05 用户定）

- **主力**：左段 = **P\* 那条流线的逆向延拓**（`singleSeed`，不做 min-T 选优）。
  新增 `SeamtParams::singleSeed`：只布 `latP0Forced` 一个种子。
- **能反推多长算多长**，不要求一定过 lonIn 那个面。`extract()` 在 `singleSeed`
  且 `G` 为空时，把那条（半截的）轨迹当核心收下。
- **左段用跳岛容差**（新增 `SeamtParams::leftLandMode`，默认 `SEAMT_LAND_SKIP_ISLANDS`）；
  右段仍用 `landMode`。
- **去掉 `(P\*+P')/2` 中点**。备选的「集合带邻近点」扫描已用 `#if 0` 注释掉。
- **拼接去重要看情况**：`leftStartsAtPstar` 为真才丢右段第 0 点。
- **兜底**：P\* 的半截反推若**没真往西走**（推进 < 0.25°）就退回旧的 min-T 选优。
  `全3.nc` 上 P\* 的反推 743 步只挪了 −0.131°（还往东，原地回旋后停滞），走的就是兜底。

## 21.2 断面必须从「经线」推广成「线段」

老域的 Γ_in/Γ_out 只能是经线。Wang 的起始断面 A.south 是**纬向**的，所以要把断面推广成线段。
做法是加一层几何小函数，**两套公式各写各的**（不在一条公式里塞 if，免得一个域的修法波及另一个）：

| 小函数 | 经向（老域） | 线段（新域） |
|---|---|---|
| `ginPoint(s)` | `(lonIn, s)`，s=纬度 | 按弧长比例内插，s=自端点 1 起算的弧长（度） |
| `ginP0Range` | `[latP0Min, latP0Max]` | `[0, 弧长]` |
| `ginSeedRange` | `[latDomMin, latDomMax]` | `[0, 弧长]` |
| `goutDir` | `(±1, 0)` | Γ_in 中点 → Γ_out 中点的单位向量 |
| `crossGout` | 跨过经线 `lonOut` | 步段与 Γ_out 线段求交，交点还须落在线段内 |

**向后兼容是可证的**：经向下 `goutDir` 给 `(±1,0)`，于是
`atan2(cross,dot) = atan2(∓v,±u) = ∓atan2(v,u)`，取绝对值后与旧的 `|atan2(v,u)|` **逐位相同**
（atan2 对第一参数是奇函数）。§21.5 的逐位回归就是这句话的验证。

## 21.3 ★「方向判据写死成朝东」是移植到非东向射流的第一堵墙

老的 `findP0` 主候选判据是 `us>0 && |atan2(v,u)| <= 45°` = **「朝东 45° 内」**。
上游黑潮在起始断面附近是**东北—北向**（方位角 +12°～+26°，甚至更偏北），
这条判据会把整条射流拒掉，退到「取模长最大」的兜底 —— P₀ 必然挑错。
改成「与 Γ_in→Γ_out 方向的夹角 ≤ jetAngMaxDeg」后才对。

## 21.4 ★ A.south(16.00°N) 不是射流的入流断面

**实测**（`E:\glorys_dl\wang\glorys_20210101.nc`，1/12°，12–36°N / 114–135°E）：

| 位置 | u | v | 判读 |
|---|---|---|---|
| **16.00°N, 122–124°E（A1 原值）** | −0.00 … **−0.25** | +0.06 … +0.09 | **西向 NEC**，不是黑潮 |
| 16.50°N, 122.20°E | **+0.132** | **+0.266** | 东北向，这才是黑潮 |
| 全域最强 18.83°N, 121.75°E | | | \|u\|=2.45 m/s |

**Wang 发表轴的起点纬度**（`kuroshio_2021/2022.nc` 共 80 天统计）：
**16.1725–16.7959°N，中位 16.5049**；经度 122.31–123.83°E。

也就是说 **A.south(16.00°N) 是段 A 的几何下边界，不是射流的入流断面** ——
段 A 的装配产物起点齐刷刷落在 ~16.5°N，比那条边界偏北 0.5°。
种子撒在 16.00°N 上只会顺着 NEC 漂向西南（实测 281 条全部漂到 (121.4, 15.4) 附近触底）。
故 Γ_in 取 **16.5°N 纬向断面，122→124°E**（经度覆盖观测到的 122.31–123.83）。

**插件里 Wang 的 kSections/kSegs 到底干什么**（`src/ncdf_kuroshio.cpp`）：
1. 候选子段的**切分与归属**（`onSection` → `collectCandidates`）：A–E 各由 south/mid/north 三条断面围成；
2. 段盒的边界（`kSegs[].latLim/lonRange`，`validate_streamline` 用）；
3. **追踪边界**（`kuroTraceBounds`）= 11 条断面 + 5 个段盒的并集**再外扩 4°**。
   所以 A1 是「段 A 的几何下边界 / 轴的纬度下限（`cutLatMin=16`）」，但**不是研究域的墙**。

## 21.6 陆地容差：做成两域各自可调的模式

`SeamtParams::landMode`（`include/ncdf_seamt.h`）：

- **`SEAMT_LAND_TRUNCATE`（默认 / 下游）**：`UVField::sample` 严格四角规则 + GSHHG 判陆即截断。
  不会造跨陆地假路径，但近岸海域被四角规则啃掉一圈，1–2 格的小岛把流线挡死。
- **`SEAMT_LAND_SKIP_ISLANDS`（上游）**：`sampleCoast` / `isSeaCoast`，2×2 有一个有效角就取值，
  流线能从被啃掉的窄条里穿过、绕过 1–2 格小岛。代价是也能从「只有一个角是海」的格子里
  **穿过小岛抄近路**（§18.4 在下游测过：轴反而更差，故下游不用）。

调法：UI「陆地容差：跳过小岛」复选框 / 预设 / 请求文件 `landmode=0|1`。
`ncdf_flags.txt` 的 `seamtCoastTolerant=1` 保留为**诊断覆盖**，优先级高于 `landMode`。

**它确实是上游那把钥匙**：同一份数据、同一 Γ_in，只切换这个开关 —

| | TRUNCATE | SKIP_ISLANDS |
|---|---|---|
| P₀ 落点 | 122.348°E（**离射流 0.15°**） | **122.174°E（正在射流上）** |
| P₀ 处 \|u\| | 0.286 | **0.297** |
| 种子带 | 122.34–123.79°E（**全在射流以东**） | **122.17–123.63°E（含射流）** |
| reasons | AGROUND=281 | AGROUND=233 + **OUTDOMAIN=48** |

四角规则在 122.30°E 附近就取不到值（有个角是陆），所以 TRUNCATE 下 P₀ 被挤到离岸侧、
种子带整个落在射流以东 —— 正是 §18.2 记过的「**一侧被挡住时集合全落在同一侧，
min-T 只能从离岸侧起跳，核心被系统性推向离岸**」。跳岛容差把这个治好了。

## 21.7 现状：G=0，卡在吕宋北部岛链（2026-11-05）

种子撒对了、方向对了（探针 20 步后从 (122.174,16.500) 走到 (122.219,16.587)，朝东北），

|---|---|---|

| (120.5, 19.0–19.1) | 42 | **OUTDOMAIN（撞西墙 lonDomMin=120.5）** |

那里是**吕宋北部岛链**。GLORYS 在 (18.83°N, 121.42°E) 有 1.11 m/s、(18.83°N, 121.75°E) 有
**2.45 m/s** 的 NNW 强流 —— 黑潮正是朝岛链冲过去的；1–2 格的小岛把它挡死。
跳岛容差救回了 48 条，但它们顺着 NNW 流**向西**跑出研究域（120.5°E），
而 Wang 的轴在 19.36°N 处位于 121.70°E，是从岛链**东侧**绕过去的。

**根因（方法论层面，不是参数没调好）**：CLAUDE.md 早有一条 ——
**Wang2026 的输出是「最大流速脊」不是「流线」**（切向偏离局部流向中位 9.4°）。
速度脊可以横切流线贴着最快水绕过岛链；而 **SEAMT 的核心必须是一条真流线**，
撞上岛链就只能截断。这是两个方法的输出性质差异，不是实现 bug。

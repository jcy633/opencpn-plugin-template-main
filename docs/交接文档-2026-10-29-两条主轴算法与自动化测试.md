## 2. 自动化测试（本轮最重要的产出）

### 2.1 用法

```bash
bash seamt_autotest.sh 'E:\nc1\海流1.nc' 0 131.0 142.0     # SEAMT
MODE=kuro bash seamt_autotest.sh 'E:\nc1\glorys_20240101.nc' 0   # Wang2026
NPTS=561 bash seamt_autotest.sh '...'                        # 覆盖集合规模
```

一条命令完成：部署 DLL → 写请求文件 → 启动 OpenCPN 并打开面板 → 自动加载文件读时次
→ 跑算法 + 全套自检 → 写报告 → **关闭 OpenCPN**。约 30 秒，无需手动点界面。

### 2.2 机制

1. 请求文件 `C:\ProgramData\opencpn\ncdf_seamt_auto.txt`（`key=value` 一行一个）
2. `ncdf_pi::Init()` 发现它 → 自动 `OnToolbarToolCallback(0)` 开面板
   （**面板是点工具栏才构造的**，钩子必须挂 `Init`，挂构造函数没用）
3. `MainDialog::maybeRunSeamtAutoTest()`（`CallAfter` 触发）→ `switchToFile` → 读时次
   → 跑算法 + 自检 → 写 `ncdf_seamt_auto_result.txt` → 请求文件改名 `.done`

**请求文件字段**：`file` / `mode`（seamt|kuro）/ `time` / `lonin` / `lonout` / `npts` /
`halfwidth` / `dt` / `latdomin` / `latdommax` / `p0min` / `p0max`

### 2.3 关键实现细节（踩过的）

- **`readTimeStepData` 的契约**：入参必须已带坐标 / 文件名 / 时间下标，它只负责读 U/V。
  必须先把 `myDataVector[idx]` 的元数据灌进 `myMessage`（`myMessage = myDataVector[idx]`），
  否则 `latValues` 为 NULL 直接失败
- **自动测试时跳过 `fillDirTree`**：`addChildren` 要读每个 nc 的元数据，
  目录里有大文件（如 130 MB 的年度数据集）会把测试挤到超时。
  注意 `setPlugIn` 里的 `SetValue` 会触发 `onDirChanged`，**两处都要挡**
- **脚本必须部署 DLL**：只写请求文件不部署，跑的是旧 DLL，参数改了没反应
- **脚本结束必须关 OpenCPN**，否则看起来像卡住（用户明确要求）

## 4. 本轮引入的「零速格填充」（`kuroZeroFill`）

### 4.1 它是什么

MATLAB 原版：

```matlab
sub_u(isnan(sub_u) | mask_grid < 1) = 0;            % 无效格点填 0
Fu = griddedInterpolant(LatGrid, LonGrid, sub_u, 'linear');
```

所以近岸点的插值是**「真实值与 0 的加权」**，而不是"四角有一无效就失败"。
流线可以穿过零速格（以零速继续走），不会在那里断掉。

我们原来的 `UVField::sample()` 是**四角有一无效即返回 false** → 流线立刻断。

### 4.2 实现方式（不污染共用件）

- `include/ncdf_uvfield.h` 新增 **`sampleZeroFill()`**，**不动 `sample()`**
  （`sample()` 与 SEAMT 共用，属控制变量）
- 新增成员 `bool zeroFillInvalid = false;`，默认 false = 现有语义
- `src/ncdf_kuroshio.cpp` 用 `sampleF(F, ...)` 统一分派（参数顺序与 `F.sample` 一致），
  12 处调用全部替换；`F.zeroFillInvalid` 在 `extract()` 里由 `kuroZeroFill` 灌入

**⚠️ 这是"复刻原版行为做验证"，不代表认可其物理合理性**（流线穿过陆地在物理上是错的）。
先证明"与原版一致"，再讨论"原版哪里不合理"——两件事分开。

## 1. Bug 1 & 2：点按钮整个软件卡死

### 现象
点插件工具栏按钮 → OpenCPN 整个界面冻结，日志停在半句。

### 证据链
`ncdf_debug.log` 最后一次点击共 66 行：

```
MainDialog constructor: ncdfReader created
onDirChanged: started -> calling fillDirTree          ← 第 1 次全树扫描
fillDirTree: ... 6 个 glorys 文件全部 "metadata OK"
addChildren: fileName=E:\nc1\kuroshio_2024.nc        ← 进入 nc_read_metadata，再没出来
fillDirTree: started, path=E:\nc1, start=1           ← 第 2 次全树扫描（无 onDirChanged 前缀）
fillDirTree: deleting all tree items                 ← 把第 1 次正在用的树全删了
addChildren: fileName=E:\nc1\glorys_20200615.nc      ← 日志到此为止，永久冻结
```

`opencpn.log` 同时段：`Caught MainLoopException, continuing...` ×3 + `glRenderbufferStorage error: 00000505`（GL_OUT_OF_MEMORY）。

### 根因
1. **目录树被扫两遍**。`setPlugIn` 里 `m_textCtrlDir->SetValue()` 触发 `onDirChanged`→`fillDirTree`，紧接着又显式调一次。第 2 次的 `DeleteAllItems()` 落在第 1 次 `addChildren` 还握着 `wxTreeItemId` 的时候。
   （CLAUDE.md 早为 `onFileButtonClick` 记过同一类坑：「SetValue 已触发 onDirChanged」，`setPlugIn` 当时漏了。）
2. **`fillDirTree` 没有重入保护**，且 `Freeze()` 之后没有异常安全的 `Thaw()`——中途一抛异常，树永久冻结、`m_isTreeUpdating` 卡 true，后续所有选择事件被挡掉。
3. **`ncdfLog` 的自旋锁没有超时也没有异常安全**。只要有一次日志调用在持锁期间出事（比如 `%s` 收到坏指针），之后每一次 `ncdfLog` 都原地自旋 → **整个程序冻结、日志永久停止**。这是"局部失败放大成整机冻结"的放大器。

### 修法
- `setPlugIn`：`SetValue` → `ChangeValue`（不触发事件），只保留一处 `fillDirTree`
- `fillDirTree`：POD 重入拒绝 + `try/catch` + 异常安全的 `Thaw()`/标志复位
- `ncdfLog`/`ncdfLogW`：加锁 3 s 超时，拿不到就写旁路 `ncdf_debug_stuck.log`；写入用 `__try/__except` 包住
- `addChildren`：`nc_read_metadata` 包 `try/catch`，异常记 `what()` 而不是逃逸

## 2. Bug 3：`nc_open` 打穿地址空间

### 现象
修完 Bug 1 后面板能开，但 `kuroshio_2024.nc` 之后**所有**文件的元数据都读不到。

### 证据链（探针）
```
[addr] before nc_open: availVirtual=1405MB
  -> nc_open(kuroshio_2024.nc) 抛 std::bad_alloc
[addr] before nc_open: availVirtual=92MB        ← 一次吃掉 1.3 GB
```

`kuroshio_2024.nc` 是 Wang2026 的主轴发布数据集，**每天每层一组**：
```
time=366  depth=30      根组只有 3 个 1-D 变量
数据集总数: 76863       366 × 30 × 7
HDF5 组数: 10980
```
`nc_open` 要为 7 万多个对象建索引 → 一次申请 1.3 GB → Win32 2 GB 地址空间打穿 → `bad_alloc`，**此后每个 `nc_open` 都失败**（连 283 KB 的小文件也一样）。

### 关键认知
- **它根本不是海流/海温数据文件**（没有 u/v/lat/lon），插件不需要打开它，是目录树把它扫进来了。
- 任何 NetCDF/HDF5 程序打开它都会吃 GB 级内存，不是本插件的 bug；插件要做的是**别主动打开**。

### 修法：目录树懒加载
`fillDirTree` 只列文件名（`SetItemHasChildren` 显示「+」），**不碰任何 nc**；`wxEVT_TREE_ITEM_EXPANDING` 触发 `onTreeItemExpanding` 才去读该文件的元数据。

- 单个文件出问题只影响它自己，失败后把「+」摘掉避免反复重试
- 这本来就是 CLAUDE.md「fillDirTree 禁止调 addChildren」那条规矩的原意，之前没守住

### 边界
即便懒加载后手动展开 `kuroshio_2024.nc`，仍会吃 1.3 GB；现在异常被隔离、只丢那一个节点，但**别在插件里展开它**。

## 3. Bug 4：点 Wang 提取按钮闪退（真凶）

### 现象
点提取按钮 → OpenCPN 直接退出，**连崩溃对话框都没有**。

### 排查过程（值得记）
1. `try/catch` 拦不住 ⇒ 不是 C++ 异常
2. `ncdf_crash.dmp` 是 0 字节、时间还停在 19:28 ⇒ 插件的 SEH 处理器**根本没触发**
3. WER 有 dump、插件没有 ⇒ 是 `std::terminate`→`abort`，或者是**栈溢出**（栈爆了 `MiniDumpWriteDump` 取不到栈，正是 0 字节）
4. 日志停在 `[kuro] extract: grid ...` 之后第一句取速度 ⇒ 定位到 `sampleF`

### 根因
```cpp
static inline bool sampleF(const UVField &F, double lonq, double latq, double &uo, double &vo)
{
    return F.zeroFillInvalid ? F.sampleZeroFill(lonq, latq, uo, vo)
                             : sampleF(F, lonq, latq, uo, vo);   // ← 调的是自己！
}
```

**`zeroFillInvalid==false` 分支无限递归自己**（本该调 `F.sample`）→ 栈溢出 → 访问违例 0xC00000FD。

这是「零速格填充」那轮 `sampleF` 统一分派重构引入的（12 处调用全换成 `sampleF`），**那次 A/B 被中断没跑完，所以一直没暴露**。

**为什么 19:15 的自动测试却跑通了**：当时 `ncdf_flags.txt` 里有 `kuroZeroFill=1` → 走 `sampleZeroFill` 分支不递归；后来只剩 `kuroThreads=8` → 走递归分支必崩。

> **教训**：重构时新写的分派函数，两个分支都要跑一遍才算验证过。只跑了一个分支 = 没验证。

## 4. Bug 5：陆地没颜色

### 根因
`ncdf_landlayer.cpp` 的 `BuildLandLayers`：

```cpp
// [步骤4] 停用精层，只建粗层 —— 验证「陆地不正常」是否由此引起   ← db59067 遗留
if (coarse && coarse->valid()) { BuildLandLayer(*coarse, ...); }
s_landBuilt = true;
```

**只建 `coarse`、`fine` 从不参与**。这是 `db59067`（渲染性能优化那轮）验证「陆地不正常」时留下的调试代码，**忘了回退**。

以前 15″+30″ 两份掩膜都在，`coarse`=30″ 全球层，所以看着正常；按用户要求丢掉 15″ 后只剩一份 → `m_landMaskCoarse` 没载入 → `coarse=NULL` → **一个图层都没建**：

```
[landlayer] active=0 hasTex=0
[landlayer] WARN: gap-fill running with NO land mask (hasTex=0) -> land painted seabed
```

补空白在没掩膜的情况下把陆地涂成了海底色。

### 修法
`NcdfLandMask *src = (coarse && coarse->valid()) ? coarse : (fine.valid() ? &fine : NULL);`
两份都在时行为与原来一致。

> **教训**：调试用的「临时关掉某功能」代码，验证完必须回退或明确标注并加 TODO。放着不管会在配置变化时炸出来，且症状离原因很远。

## 5. Bug 6：提取 49 秒（89 倍性能问题）

### 现象
提取要 ~49 秒，GUI 全程阻塞，用户以为卡死。

### 我先猜错了两次（记下来别再犯）
| 猜想 | 措施 | 实测 | 结论 |
|---|---|---|---|
| cache 局部性：u/v 数组 70 MB，插值全 cache miss | `UVField::window()` 裁到追踪边界（282×247） | 31 060 → 29 365 ms | **错**。只快 5% |
| 计算量太大 | — | — | 一半对，但没找到项 |

### 决定性测量：CPU vs 墙上时间
```
8 线程: cpu=124546ms wall=48752ms -> parallel x2.55
1 线程: cpu= 51437ms wall=51862ms -> parallel x0.99
```
**8 线程把 CPU 从 51 s 烧到 124 s，墙上时间却几乎没降** ⇒ 多出的 73 s 全在线程互相踩，且"真实计算" 51 s 本身就偏高。

### 真凶
```cpp
static int kuroFlagInt(const char *key) {
    FILE *fp = fopen("C:\\ProgramData\\opencpn\\ncdf_flags.txt", "r");  // 每次调用都开文件
    ... fgets 循环 ... fclose(fp);
}
```
而 `kuroAvgZero()` 在**每条候选段**上调用一次（`candSegs=687829`）= **每轮 68.8 万次 fopen/fclose**。8 线程并发开关同一个文件，CRT 文件锁被踩爆。

### 修法
1. `kuroFlagInt` 缓存文件内容 **2 s**（改完 flags 存盘后停 2 秒重跑即生效），POD 自旋锁保护
2. `collectCandidates` 里的 `kuroAvgZero()` 提到函数开头读一次

### 结果（同一文件 `海流1.nc`，工作量计数逐项相同）
| | 改前 | 改后 | |
|---|---|---|---|
| 墙上时间 | 48 789 ms | **547 ms** | **89×** |
| CPU 总量 | 124 546 ms | **4 375 ms** | 28× |
| 并行效率 | x2.55 / 8 | **x8.12 / 8** | 满速 |
| 结果 | nAxis=177 len=2043km mean=0.74 max=1.17 segs=5/5 | **完全相同** | ✓ |

`integSteps=4199611 / candSegs=687829 / samplePts=54051210 / loopPairs=58257078` 改前改后**一个不差**，证明没有动任何计算。

> **教训 1**：**诊断开关绝不能在热路径上做 I/O**。渲染那边早有「每 30 次渲染重读一次」的限流，kuro 这边没有。
> **教训 2**：「8 线程没变快」不是"并行化没用"，先看 **CPU 总量 vs 墙上时间**——CPU 涨了 2.4 倍说明在互相踩，不是算力不够。
> **教训 3**：性能问题别猜。加**工作量计数**（调用次数）+ **CPU/墙 比值**，一轮就能定位；靠猜改了两轮都没中。

## 6. 测试型 / 使用型 开关（新增）

**问题**：自动化测试会在插件加载期强行构造面板跑算法，一旦请求文件残留就把日常使用整个弄坏（Bug 1 就是这么触发的）。

**机制**：`C:\ProgramData\opencpn\ncdf_mode.txt`
- 写 `test` → 自动化测试入口生效
- 写 `use`（或文件不存在，**默认**）→ 完全不生效，哪怕残留了 `ncdf_seamt_auto.txt`

判定入口统一走 `ncdfAutoTestRequested()`（`ncdf.cpp`），三处调用点（`ncdf_pi::Init`、`setPlugIn`、`onDirChanged`）全走它。
不缓存文件内容，改完存盘即生效。

`seamt_autotest.sh` 会临时写 `test`，脚本退出时用 `trap` 恢复原状。

## 7. 掩膜取舍（15″ vs 30″）

用户决定：**统一用 30″ 掩膜，不用 15″ 那份**。理由与覆盖度实测：

| 算法 | 实际用到的范围 | 15″（12–36°N / 112–136°E） | 30″（全球） |
|---|---|---|---|
| Wang2026 | 断面 A–E：16.00–31.25°N / 118.00–130.38°E；追踪边界+4°：12.00–35.25°N / 114.00–134.38°E | ⚠️ 勉强（纬度下边界正压在掩膜边上） | ✓ |
| SEAMT | `lonIn=131.0 → lonOut=142.0`；实测子射流到 **37.6°N** | ❌ **盖不住**（只到 136°E / 36°N） | ✓ |

**挪回 15″ 会坏 SEAMT。** 而且掩膜与性能无关（陆海判定只在撒种子时调 9257 次）。

`loadLandMaskFiles` 现在**主动丢弃 15″**（只在还有别的候选时丢），并把 `30s` 排最优先。原先 `15s`/`30s` 同 rank=0，谁排前面看文件枚举顺序。

## 8. 其它改动

- **撒种子限定到 A–E 段盒**（`kSegs`，论文 Table 1 的硬编码断面）：原先是 15–32°N / 115–132°E 的大框加 L 形廊道，比研究域大一倍多。改后种子 22292 → 9257。
  论文原话是 *"seed points were placed on a regular grid … covering **the study domain**"*，研究域正是这五段，所以这更贴原论文而非妥协。
- **`UVField::window()`**：视野裁到追踪边界（±4°）。纯指针/计数变换，结果逐位不变。子矩形在内存里不连续，故新增 `stride` 成员保存原行宽（不裁剪时 `stride == nlon`，SEAMT 走 `bind()` 完全不受影响）。
- **`avgSpeed` 双趟采样合并成一趟**：原先第二遍只为数有效点个数、结果全扔。`sampleF` 是纯函数，语义不变。
- **`detectLoops` 去掉内层 `sqrt`**：`sqrt(x) < t` ⟺ `x < t*t`（`t>0`），O(n²) 内层省一个量级。
- **`nc_read_metadata` 探针**（`[ncdfmeta]`）、**地址空间探针**（`[addr]`）、**工作量计数**（`[kuro][work]`）都保留，日后定位问题直接用。
